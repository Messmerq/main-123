# Эмулятор UNIX-оболочки: вариант 17

Практическая работа № 1 по дисциплине «Конфигурационное управление»,
ИКБО-71-25, РТУ МИРЭА, 2026/2027. Язык реализации: Python.

Консольный эмулятор работает с виртуальной файловой системой (VFS),
загружаемой из CSV. Команды `ls`, `cd`, `head`, `whoami`, `touch`, `exit`
исполняются самим приложением. Реальная оболочка ОС не вызывается.
Изменения VFS существуют только в оперативной памяти.

Подробный отчет по пяти этапам: [Main.md](Main.md).

## Требования и быстрый запуск

Нужен Python 3.10 или новее. Сторонние библиотеки не требуются.
Запускайте команды из корня репозитория.

```sh
python3 src/main.py
# macOS / Linux: скрипт запуска
sh run.sh --vfs examples/deep.csv
# Windows: тот же Python CLI без shell-скрипта
python src/main.py --vfs examples/deep.csv
```

Сборка исполняемого файла не требуется. Проверка компиляции и тестирование:

```sh
python3 -m compileall -q src tests
python3 -m unittest discover -s tests -v
# При наличии make:
make check
make test
make run
```

## Настройки

| Параметр | По умолчанию | Назначение |
| --- | --- | --- |
| `--vfs PATH` | `examples/deep.csv` | Физический CSV-файл VFS |
| `--prompt TEXT` | `{vfs}:{cwd}$ ` | Приглашение REPL |
| `--script PATH` | Не задан | Стартовый UTF-8 скрипт |
| `--no-repl` | Выключен | Завершиться после скрипта без интерактива |
| `-h`, `--help` | - | Справка по параметрам приложения |

`{vfs}` заменяется именем CSV без расширения, `{cwd}` - текущим путем VFS.
Если пользовательское приглашение не содержит имя VFS, добавляется `[имя]`.
Параметры выводятся при каждом запуске для отладки.
Пути `--vfs` и `--script` относятся к реальной ОС; пути команд - только к VFS.
`run.sh` переходит в корень проекта; для внешних файлов удобны абсолютные пути.
Переменная `PYTHON` у `run.sh` и Makefile позволяет выбрать интерпретатор.

```sh
sh run.sh --vfs examples/deep.csv --prompt '{vfs}:{cwd}> '
sh run.sh --script examples/stage4.txt --no-repl
```

Строки стартового скрипта отображаются вместе с приглашением и результатом.
`#` начинает комментарий, в том числе в конце строки. Пустые строки допустимы.
При ошибке печатаются имя скрипта и номер строки; выполнение продолжается.
`exit` прекращает скрипт и не запускает REPL. Код завершения: 0 при успехе,
1 при ошибках загрузки/скрипта, 2 при неверных аргументах CLI (`argparse`).
Ошибки интерактивных команд выводятся в REPL, не завершая сеанс.

## Команды

| Команда | Поведение и поддерживаемые режимы |
| --- | --- |
| `ls [PATH...]` | Имена прямых потомков; без пути - текущий каталог |
| `ls -a [PATH...]` | Включает скрытые имена, начинающиеся с точки |
| `ls -l [PATH...]` | Тип узла и размер содержимого в байтах |
| `ls -al`, `ls -la` | Совмещение режимов; допустимы и отдельные `-a -l` |
| `cd [PATH]` | Сменить каталог; без аргумента - корень `/` |
| `head [-n N] FILE...` | Первые 10 строк или N строк; N - целое >= 0 |
| `whoami` | Имя текущего пользователя реальной ОС |
| `touch FILE...` | Создать пустые файлы или обновить время существующих узлов |
| `exit` | Завершить сеанс; аргументов нет |

Абсолютные и относительные пути, `.` и `..` поддерживаются.
Подъем выше `/` остается в виртуальном корне. Каталоги в `ls` имеют суффикс `/`.
Для нескольких файлов `head` добавляет заголовки с именами.
Бинарные данные хранятся без потерь; при выводе `head` неверный UTF-8
заменяется символом `�`. `touch` не создает отсутствующие родительские каталоги
и не стирает существующее содержимое; его временные метки хранятся в `Node`.

Парсер по заданию простой: `str.split()` по пробельным символам.
Кавычки, экранирование, раскрытие `$HOME`, конвейеры, перенаправления,
подстановки и имена с пробелами не поддерживаются. `#` всегда начинает комментарий.
Неизвестные команды, опции, лишние аргументы и неверные пути вызывают ошибку.
Опции команд ограничены перечисленными в таблице режимами.

## Формат VFS

CSV в UTF-8 (допустим BOM), заголовок строго `path,type,data`.

```csv
path,type,data
/,dir,
/docs,dir,
/docs/hello.txt,file,SGVsbG8K
```

`path` - канонический абсолютный POSIX-путь; `type` - `dir` или `file`;
`data` - base64 байтов файла, для каталога обязательно пустое поле.
Пример выше содержит файл с текстом `Hello` и переводом строки.
Корень `/` создается автоматически; его строку можно указать явно.
Все остальные родительские каталоги нужно перечислить в CSV.
Порядок строк произвольный: родители могут находиться после детей.
Дубликаты, пути с `..`, неизвестные типы, неверный base64,
неправильные столбцы и отсутствующие родители отклоняются.

Вложенность задается полными путями, например
`/docs/projects/python/notes.txt`. VFS не распаковывается на диск.
`touch` меняет словарь узлов в памяти; повторный запуск читает исходный CSV.

| Пример | Содержимое |
| --- | --- |
| `examples/minimal.csv` | Только корень |
| `examples/files.csv` | Несколько файлов, включая бинарный |
| `examples/deep.csv` | Скрытый файл, текст и 3 уровня вложенных каталогов |

## Проверочные сценарии

```sh
python3 src/repl.py
python3 src/config.py --vfs examples/deep.csv --script examples/stage2.txt --no-repl
sh scripts/test_config.sh
sh scripts/test_vfs.sh
sh scripts/demo.sh
```

В демонстрационных скриптах есть намеренные ошибки. Запуск приложения
с такими файлами возвращает 1; shell-обертки считают это ожидаемым результатом.
`stage1.txt` предназначен для ввода в прототип:

```sh
python3 src/repl.py < examples/stage1.txt
```

`stage2.txt` проверяет комментарии и настройки, `stage3.txt` - навигацию,
`stage4.txt` - основные команды и ошибки, `stage5.txt` - изменения в памяти.
После автоматических сценариев рекомендуется вручную повторить команды
в интерактивном режиме для очной защиты.

## Структура и функции

- `src/repl.py`: `parse` разделяет токены, `prototype` исполняет заглушки,
  `main` запускает интерактивный прототип этапа 1.
- `src/config.py`: `arguments` читает настройки, `run_script` исполняет
  стартовые строки; `PrototypeShell` и `main` сохраняют прототип этапа 2.
- `src/main.py`: `main` загружает VFS и управляет запуском;
  `repl` читает команды, обрабатывая EOF и Ctrl+C.
- `src/vfs.py`: `Node` хранит тип, байты и время изменения;
  `Vfs.__init__` создает корень, `load` читает CSV, `add_row` проверяет строку,
  `validate_path` проверяет путь, `validate_parents` проверяет родителей,
  `resolve` нормализует пути,
  `get` ищет узел, `directory` проверяет каталог, `children` сортирует потомков,
  `touch` создает/обновляет узлы в памяти.
- `src/shell.py`: `Shell.__init__` создает сеанс, `prompt` строит приглашение,
  `execute` выбирает команду; `ls`, `cd`, `head`, `whoami`, `touch`, `exit`
  реализуют команды. `list_entry` форматирует вывод `ls`,
  `ls_arguments` проверяет опции, `list_path` форматирует один путь,
  `no_arguments` проверяет команды без аргументов.
- `tests/test_emulator.py`: изолированные тесты парсера, CLI, VFS, команд,
  ошибок, сценариев, REPL и неизменности физического CSV.
- `examples/`: три CSV и сценарии пяти этапов.
- `scripts/`: проверка параметров, вариантов VFS и демонстрация команд.
- `run.sh`, `Makefile`, `.gitignore`: запуск, проверки и исключение артефактов.

Функции документированы docstring. Исходные файлы не требуют установки пакета.
