# Практическая работа № 1. Вариант 17

**Дисциплина:** Конфигурационное управление.
**Группа:** ИКБО-71-25. **Язык:** Python 3.10+.

## Цель

Разработать консольный эмулятор UNIX-подобной оболочки с конфигурацией,
виртуальной файловой системой в формате CSV и командами варианта 17.
Все операции над VFS выполняются в памяти.

## Этап 1. REPL

Реализован самостоятельный прототип `src/repl.py`:

- Консольный цикл ввода с именем VFS в приглашении.
- Разделение команды и аргументов по пробелам (`str.split`).
- Заглушки `ls` и `cd`, выводящие имя и список аргументов.
- Завершение по `exit`, EOF и Ctrl+C.
- Сообщения о неизвестной команде и неверных аргументах.

```sh
python3 src/repl.py
```

Пример интерактивного диалога:

```text
prototype-vfs:/$ ls /docs
ls: ['/docs']
prototype-vfs:/$ cd a b
Ошибка: cd: ожидается не более одного пути
prototype-vfs:/$ unknown
Ошибка: unknown: неизвестная команда
prototype-vfs:/$ exit
```

Сценарий воспроизведения: `examples/stage1.txt`.

## Этап 2. Конфигурация

Самостоятельный прототип `src/config.py` добавляет `--vfs`, `--prompt`,
`--script` и диагностический вывод параметров. Финальная точка входа -
`src/main.py`; она использует те же функции настройки и исполнения скриптов.

Стартовый скрипт использует комментарии Python (`#`), отображает ввод и вывод,
продолжает работу после ошибки и указывает файл/номер строки.
Для автоматического завершения доступен дополнительный флаг `--no-repl`.
Пользовательское приглашение сохраняет имя VFS.

```sh
python3 src/config.py --vfs examples/deep.csv --prompt 'demo> ' --script examples/stage2.txt --no-repl
sh scripts/test_config.sh
```

Все заданные параметры видны при запуске. Скрипты реальной ОС находятся
в `scripts/`; каждый передает путь VFS, приглашение и стартовый сценарий.

## Этап 3. VFS

`src/vfs.py` загружает CSV в словарь абсолютных POSIX-путей.
Узел содержит тип, байтовое содержимое и время изменения.
Вложенность представлена полными путями. Данные файлов кодируются в base64.
Распаковки и изменения исходного CSV при выполнении команд нет.

```csv
path,type,data
/,dir,
/docs,dir,
/docs/hello.txt,file,SGVsbG8K
```

Предусмотрены три источника: `minimal.csv`, `files.csv`, `deep.csv`.
Последний содержит `/docs/projects/python/notes.txt` с тремя уровнями каталогов.
Проверяются формат, каноничность путей, дубликаты, типы, base64 и родители.

```sh
sh scripts/test_vfs.sh
sh run.sh --vfs examples/deep.csv --script examples/stage3.txt --no-repl
```

Во втором вызове код 1 ожидаем: сценарий намеренно содержит неверный путь.

## Этап 4. Основные команды

В `src/shell.py` реализована диспетчеризация:

| Команда | Режимы |
| --- | --- |
| `ls` | Текущий/указанный путь, несколько путей, `-a`, `-l`, `-al`, `-la` |
| `cd` | Абсолютный/относительный путь, `.`, `..`, корень без аргументов |
| `head` | Первые 10 строк; `-n N`, N >= 0; несколько файлов |
| `whoami` | Реальное имя пользователя ОС |
| `exit` | Завершение без аргументов |

```sh
sh run.sh --script examples/stage4.txt --no-repl
```

Пример интерактивного сеанса финального приложения:

```text
deep:/$ cd /docs/projects/python
deep:/docs/projects/python$ ls
notes.txt
deep:/docs/projects/python$ head -n 1 notes.txt
Вариант 17
deep:/docs/projects/python$ cd /missing
Ошибка: /missing: путь не найден
```

Для `whoami` вывод зависит от учетной записи реальной ОС.
Некорректные команды и аргументы не завершают интерактивный сеанс.
Сценарий этапа содержит успешные случаи, все поддержанные режимы и ошибки.

## Этап 5. Дополнительная команда

`touch FILE...` создает пустые файлы или обновляет время существующих узлов.
Содержимое существующего файла сохраняется. Родитель должен существовать.
Изменения остаются только в объекте VFS; исходный CSV остается неизменным.

```text
deep:/$ touch /new.txt /second.txt
deep:/$ head /new.txt
deep:/$ ls -l /new.txt
file      0 new.txt
deep:/$ touch /missing/file
Ошибка: /missing: путь не найден
```

```sh
sh run.sh --script examples/stage5.txt --no-repl
sh scripts/demo.sh
```

## Проверка и воспроизведение

```sh
python3 -m compileall -q src tests
python3 -m unittest discover -s tests -v
```

Тесты проверяют парсер и заглушки, CLI и приглашение, base64 и вложенность,
поврежденные CSV, навигацию, все команды и их ошибки, комментарии и `exit`,
интерактивный сеанс, сохранение содержимого при `touch` и побайтовую
неизменность физического CSV. Отдельно проверяется исчезновение созданного
в памяти файла после повторной загрузки VFS.

Примеры диалогов выше служат инструкцией для воспроизведения.
Автоматическая проверка не заменяет очную демонстрацию и защиту студентом.
